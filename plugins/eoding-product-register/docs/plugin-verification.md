# 상품 등록 플러그인 검증 — 2026-10-15

현재 배포 버전: **0.4.2**. 설치 진입점은 `scripts/plugin-start.mjs`, MCP 서버는 `src/plugin-mcp.mjs`이며 도구 26개를 제공합니다. 마켓플레이스는 이 저장소의 `plugins/eoding-product-register`를 설치합니다.

## 0.4.2 일정표 속도 개선

- FIT 일정의 일차 추가/선택, 단계 추가/삭제, 유형 전환, 저장 뒤 0.8~1.5초 고정 대기를 제거하고 실제 노드 수·선택 일차·입력칸·진행 중 AJAX 종료를 기다립니다. 한 번 누른 버튼이 늦게 반영돼도 반복 클릭하지 않습니다. 저장 전후 같은 상품·계정을 검사하고 전체 일정 독립 재조회는 유지합니다.
- 6단계(직접입력 3 + 관광지 3) 동일 모의 화면에서 이전 12,573ms → 개선 844ms. 두 경로의 저장 payload가 같고 POST는 각각 1회입니다. 단계 전환이 1.4초 걸리는 화면·초과 단계 삭제·무응답 추가 버튼·계정/상품 변경도 검사합니다.
- 패키지 일차 상태는 동일한 기본정보 검증 뒤 일정·식사·호텔 연결을 하나의 DOM 스냅샷으로 읽습니다. 브라우저 호출에 2ms 지연을 넣은 동일 fixture에서 55회/939ms → 7회/78ms였고 반환 필드가 모두 일치했습니다. 중복·숨은 선택·비정상 식사 입력은 계속 거부하며 저장 전후 독립 서버 조회를 생략하지 않습니다.
- 위 숫자는 로컬 브라우저 fixture 측정이며 실제 ERP 전체 등록 시간이나 20분 목표 달성 측정이 아닙니다. 이번 검증에서 실제 상품/일정을 저장하지 않았습니다.

- 패키지·FIT·콘텐츠 요청을 초기에 구분해 필요한 계약만 읽습니다. 현재 로그인과 같은 범위의 기존 사용자 위임을 유지하며 원문 사진만 사용하는 0.4.0 정책을 보존합니다.
- 콘텐츠 검토의 지역·동명 검색은 최대 4개씩 묶고 실패한 묶음의 조회가 모두 끝난 뒤 오류를 반환합니다. 결과 순서와 정확한 도시·이름 대조는 유지합니다.
- 콘텐츠 저장은 `running`을 반환하고 `product_import_get({id,compact:true}).contents`에서 단계·완료 개수·최종 생성/재사용/사진 없음 결과를 읽습니다. 실행 중 공유 세션 변경을 차단하며 close는 저장·독립 재조회 완료를 기다립니다.
- 원문·이미지 검토 바인딩과 저장 직전 계정을 확인합니다. 저장 시도 장부만 있고 조회되지 않는 항목 또는 저장 번호가 달라진 항목은 자동 재생성을 차단합니다. 중단된 running은 완료로 오인하지 않도록 대사 필요 상태를 반환합니다.
- 검사는 격리 fixture이며 실제 ERP 상품·콘텐츠를 생성하거나 변경하지 않았습니다. 실제 전체 등록 20분 달성을 의미하지 않습니다. 전체 회귀는 GitHub Actions의 Windows/Linux 결과로 별도 확인합니다.

## 실제 ERP 확인과 검증 경계

자동 검사는 실제 공통 실행기와 Chromium을 사용하지만 ERP 요청은 격리된 가상 화면에서 처리합니다. 가상 기본상품 생성은 `basic-simulated-ui`이며 실제 ERP를 변경하지 않습니다.

별도 실제 ERP 시험에서 기존 비공개 테스트 상품의 기본정보, 이미지 6장, 상세/참조정보, 4일 일정과 시즌·요금을 모두 저장하고 전체 독립 재조회를 완료했습니다. AI가 사용자의 명시적 위임으로 실제 승인 폼을 제출했고, 마지막 시즌 저장 후 화면의 빈 추가 항공편 칸을 읽는 오류가 나자 저장을 반복하지 않고 읽기 전용으로 대사했습니다. 결과는 `reconciled-read-only`, `finalCheck.status=verified`, 대사 중 추가 저장 0건입니다. 원래 실패 이력과 소비된 실행 예약은 보존하며, 검증 결과는 별도 기록입니다.

자동 테스트 통과와 실제 ERP 완료는 별개입니다. 위 실제 확인은 여러 중단의 복구와 최종 재조회를 포함한 한 건입니다. 최신 버전으로 새 원문 접수부터 끝까지 중단 없이 실행하는 별도 운영 검증을 뜻하지 않습니다. 모든 ERP 화면 변형, 모든 AI 앱/직원 PC, 원문 접수부터 실등록까지의 20분 목표는 검증하지 않았습니다. GitHub Actions에는 Windows/Linux 검사를 구성했으며 원격 실행 결과는 해당 워크플로에서 확인합니다.

로컬 stdio MCP를 제공하며 웹 전용 AI용 원격 HTTP MCP는 제공하지 않습니다. 0.1.2에서는 행사 생성이 제외됐으며 0.2.0은 명시한 KRW 출발일 1건의 행사 생성과 독립 재조회를 추가했습니다. 호텔 배정, 판매 공개, 임의의 기존 상품 덮어쓰기는 제외됩니다. 로그인은 사용자가 직접 하며, 승인 폼은 사용자가 제출하거나 명시적으로 위임한 AI가 같은 검토 범위로 제출합니다. `approval-submitted`는 폼 제출 상태이며 저장 완료를 뜻하지 않습니다.
