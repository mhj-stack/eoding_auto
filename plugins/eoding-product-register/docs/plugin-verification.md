# 상품 등록 플러그인 검증 — 2026-10-13

현재 배포 버전: **0.2.0**. 설치 진입점은 `scripts/plugin-start.mjs`, MCP 서버는 `src/plugin-mcp.mjs`이며 도구 16개를 제공합니다. 마켓플레이스는 이 저장소의 `plugins/eoding-product-register`를 설치합니다.

## 0.2.0 확인

- GitHub 배포본의 최종 검사 28개 통과: 설치/마켓플레이스 연결·MCP·입력 준비·시간 측정·행사/이어하기·계정 인식 25개와 새 대시보드 계정 복구 3개. 배포본은 로컬 캐시 패치 도구와 개인 실행 자료를 포함하지 않습니다.
- 최종 플러그인 검사 31개 통과: 위임 승인·CSRF·범위 변경·중복 제출 차단, 상품/행사 완주, 누락 시즌부터 이어하기, 이미지 일괄 수집, 원문 보충, 시간 측정, 설치/도구 계약.
- 이후 행사 담당자 바인딩까지 반영한 최종 행사 검사 4개 통과. 독립 가격·항공·복사 일정 조회, 유류할증료 불일치 거부, 기존 행사 중복 생성 차단, 시즌 준비 중단 후 기본/이미지/일정 재저장 없이 시즌과 행사만 저장하는 경로를 확인했습니다.
- 첫 원격 전체 회귀에서 Windows 임시 경로 별칭과 Linux 오프라인 시작 시점에 따른 검사 실패를 확인했습니다. 복구 모의 기록은 정규 경로로 만들고, 오프라인 시작은 모의 서버를 실제로 중지해 재현하도록 수정했습니다. 경로 별칭 재현·시즌 복구·브라우저 복원 검사 7개 통과. 운영 코드의 증거 대조와 쓰기 제한은 변경하지 않았습니다. 최신 전체 회귀 결과는 GitHub Actions에서 확인합니다.
- 스킬 공식 `quick_validate.py` 검사 통과. 로컬 설치 스크립트는 별도 모의 설치 경로에서 백업과 복사 후 해시 검증을 확인했습니다.
- 위 검사는 네트워크가 차단된 모의 ERP입니다. 실제 ERP의 신규 저장·수정·중복 상품 생성은 이번 개선 검증에 사용하지 않았습니다. 0.2.0으로 실제 ERP에서 20분 안에 끝나는 운영 측정은 미완료입니다.
- 20분은 사용자 대기를 포함한 전체 경과 시간입니다. 사용자 대기 제외 시간도 별도로 표시하며, 초과해도 저장 중인 작업이나 최종 검증을 생략하지 않습니다.

## 이전 0.1.2 기록

아래의 284개 검사와 실ERP 기록은 원래 설치본 문서에 남아 있던 이전 버전의 기록이며, 이번 개선본의 신규 성능 측정이 아닙니다.

## 확인한 내용

- 최종 전체 회귀 검사: Windows / Node 24.19.0, **284개 통과**, 실패·취소·건너뜀 0, 종료 코드 0. 약 8분 35초 소요. 검사 전후 소스·테스트·설정 123개 파일의 해시가 일치했으며, 이후 변경은 테스트 파일 끝의 빈 줄 정리와 문서뿐입니다.
- 사용자 위임 승인: 관련 검사 13개 통과. 현재 검토의 작업·회사·계정·계획·범위를 확인한 뒤 기존 localhost 폼을 실제 제출합니다. CSRF·버전·세션·만료·단일 실행 검증을 유지하고 제출자와 사용자의 직접 위임 요청을 별도 기록합니다. 외부 주소와 리다이렉트는 차단합니다.
- 시즌 화면 전환·검색·저장·재조회: 최신 관련 검사 33개 통과. 외부 통계 요청은 계속 차단하면서 이를 ERP 저장으로 오인하지 않습니다. ERP 자체의 예상 밖 변경 요청과 중복 저장은 실패 처리합니다.
- 부분 저장 복구: 원본 승인·계획·저장 영수증·사용된 예약·중단 기록을 대조하고 독립 재조회합니다. 이미 저장된 이미지·상세·일정을 재실행하지 않고 남은 시즌만 새 실제 검토로 처리합니다. 쓰기 허가나 결과가 불명확하면 무전송 복구를 허용하지 않습니다.
- 실제 위젯 대응: 비동기 상세 입력란, 참조정보 드롭다운, 탭의 표시 대기, Select2 결과의 요청/검색어 연결, 제목 입력칸이 없는 일정, 동일 이미지의 검색·재사용을 검사합니다.
- 이미지 파일의 해시·MIME·필드·CDN 내용과 동일 폼의 인증 필드를 확인합니다. 추가 파일·중복 필드·승인과 다른 값은 차단합니다.
- 0.1.2 배포 후보의 격리 설치 준비 완료: 잠금 의존성 96개, Chromium, Python/openpyxl 실행 환경을 준비했습니다.
- 기존 설치 검사: 분리된 Codex CLI 환경의 마켓플레이스 추가/설치, 설치 캐시에서 MCP 연결·스키마·가상 엑셀 원문 읽기, 이동된 Python 환경, 격리 Chromium 실행을 확인했습니다. 이 최초 설치 검사는 0.1.1 당시 도구 10개 기준입니다.
- 배포 파일은 공개 소스만 포함합니다. 실제 상품 자료, 브라우저 프로필, 쿠키, 개인 실행 기록과 설치 의존성은 제외합니다.

## 실제 ERP 확인과 검증 경계

자동 검사는 실제 공통 실행기와 Chromium을 사용하지만 ERP 요청은 격리된 가상 화면에서 처리합니다. 가상 기본상품 생성은 `basic-simulated-ui`이며 실제 ERP를 변경하지 않습니다.

별도 실제 ERP 시험에서 기존 비공개 테스트 상품의 기본정보, 이미지 6장, 상세/참조정보, 4일 일정과 시즌·요금을 모두 저장하고 전체 독립 재조회를 완료했습니다. AI가 사용자의 명시적 위임으로 실제 승인 폼을 제출했고, 마지막 시즌 저장 후 화면의 빈 추가 항공편 칸을 읽는 오류가 나자 저장을 반복하지 않고 읽기 전용으로 대사했습니다. 결과는 `reconciled-read-only`, `finalCheck.status=verified`, 대사 중 추가 저장 0건입니다. 원래 실패 이력과 소비된 실행 예약은 보존하며, 검증 결과는 별도 기록입니다.

자동 테스트 통과와 실제 ERP 완료는 별개입니다. 위 실제 확인은 여러 중단의 복구와 최종 재조회를 포함한 한 건입니다. 최신 버전으로 새 원문 접수부터 끝까지 중단 없이 실행하는 별도 운영 검증을 뜻하지 않습니다. 모든 ERP 화면 변형, 모든 AI 앱/직원 PC, 원문 접수부터 실등록까지의 20분 목표는 검증하지 않았습니다. GitHub Actions에는 Windows/Linux 검사를 구성했으며 원격 실행 결과는 해당 워크플로에서 확인합니다.

로컬 stdio MCP를 제공하며 웹 전용 AI용 원격 HTTP MCP는 제공하지 않습니다. 0.1.2에서는 행사 생성이 제외됐으며 0.2.0은 명시한 KRW 출발일 1건의 행사 생성과 독립 재조회를 추가했습니다. 호텔 배정, 판매 공개, 임의의 기존 상품 덮어쓰기는 제외됩니다. 로그인은 사용자가 직접 하며, 승인 폼은 사용자가 제출하거나 명시적으로 위임한 AI가 같은 검토 범위로 제출합니다. `approval-submitted`는 폼 제출 상태이며 저장 완료를 뜻하지 않습니다.
